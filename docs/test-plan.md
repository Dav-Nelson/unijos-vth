## Affected Pages/Routes

- `/admin/rotations` — admin assigns students to clinic/lab blocks for the semester
- `/admin/rotations/schedule` — weekly view: who is in which clinic this week
- `/api/rotations` — CRUD for rotation records (admin only)
- `/api/rotations/schedule?week=YYYY-WW` — weekly schedule query
- `/api/invoices` — create ambulatory estimate (Stage 1)
- `/api/invoices/:id` — update invoice status through lifecycle
- `/api/payments` — record deposit payment (Stage 1) or final payment (Stage 2)
- `/billing/ambulatory/:id` — ambulatory invoice view with deposit + final receipt print

## Key Interactions to Verify

**Rotation:**
- Admin assigns a student to Small Animal Clinic for a 3-week block — verify student can see clinic cases
- Admin assigns a student to Pathology Lab — verify this does NOT grant case access (display only)
- Admin views weekly schedule — all students across all clinics and labs shown in one view
- Student rotation expires (end_date passes) — verify read-only access, no new drafts
- Attempt to create overlapping rotation for same student — expect clear error

**Ambulatory Billing:**
- Receptionist creates ambulatory case → creates estimate with travel_fee (required) → Stage 1 invoice created
- Receptionist records deposit payment → receipt generated with unique receipt_number
- Invoice status moves ESTIMATED → DEPOSIT_PAID after deposit recorded
- Team returns from farm → receptionist logs return + updates invoice with actual charges
- Invoice status moves DEPOSIT_PAID → VISIT_COMPLETED → FINAL_INVOICE
- Receptionist records final payment (balance only) → final receipt generated
- Invoice reaches FULLY_PAID

## Edge Cases

**Rotation:**
- Student access on exactly end_date (last day of rotation): should still have access
- Student access on end_date + 1 day: must be read-only
- Lab sub-rotation: entity_type=LAB should appear on admin schedule but grant NO case access
- Creating rotation for a student already in rotation for same period: should be rejected

**Ambulatory Billing:**
- Enter deposit_amount > estimated_total: should be rejected (CHECK constraint)
- Attempt ESTIMATED → VISIT_COMPLETED (skipping DEPOSIT_PAID): must fail with INVALID_TRANSITION
- Attempt to go backward (FULLY_PAID → FINAL_INVOICE): must fail
- travel_fee not entered at estimate creation: required field, form should not submit
- Deposit receipt and final receipt: both printable, different receipt numbers

## Critical Paths

1. Full ambulatory billing flow: create case → estimate → deposit receipt → farm visit → final invoice → balance payment → final receipt (end-to-end Playwright test)
2. Student rotation access boundary: assigned → active (can see cases) → expired (read-only only) — Vitest integration test with real Supabase RLS + date injection
3. Concurrent invoice status update: two users updating same invoice simultaneously — DB trigger catches invalid transition
4. Admin schedule view: shows correct students for the current week across all clinics and labs

## Test Framework
- Unit + Integration: Vitest (with Supabase local dev — real PostgreSQL)
- E2E: Playwright
- Critical: Integration tests for rotation RLS boundary MUST use real Supabase local (not mocked)
